# Docker Volumes & Persistence Study Guide

## Lecture 1: Understanding Docker Volumes

Docker containers are designed to be ephemeral. This means that by default, any data created or modified within a container is lost once that container is deleted. Volumes are the preferred mechanism for persisting data generated by and used by Docker containers.

### Core Concepts

  * **Ephemeral Nature**: Containers are temporary. Starting a new container from an image resets the state to the original image definition.
  * **Persistence**: The ability for data to outlive the lifecycle of a single container.
  * **Volumes**: A filesystem that lives outside of the container on the host machine but can be accessed and modified by the container.

### Deep Explanation

Think of a standard container like a live-boot USB drive: you can change settings while it's running, but once you pull it out and plug it back in, everything is back to factory settings. A **Volume** is like plugging in a separate external hard drive alongside that USB; you can save your work there, and it will still be there even if you swap out the USB drive for a newer version.

### Key Takeaways

  * Stopping and restarting a container preserves changes, but deleting a container and starting a new one from the same image does NOT.
  * Volumes allow applications like Ghost, Grafana, or WordPress to maintain state (like posts or user data) across container recreations.
  * A well-containerized application should be replaceable without losing critical data.

### Summary Notes

Volumes solve the problem of data loss in ephemeral environments by decoupling the storage from the container's lifecycle.

## Lecture 2: Working with Volumes & Ghost CMS

This session covers the practical application of volumes using the Ghost Content Management System (CMS) as a primary example.

### Core Concepts

  * **Named Volumes**: Specific storage units created and managed by Docker that can be attached to containers by name.
  * **Environment Variables**: Key-value pairs used to configure the application environment inside the container (e.g., `NODE_ENV`).
  * **Mounting**: The process of attaching a volume to a specific path within the container's filesystem.

### Syntax & Examples

**Running a Ghost Container with a Volume:**

``` bash
docker run -d \
  -e NODE_ENV=development \
  -e url=http://localhost:3001 \
  -p 3001:2368 \
  -v ghost-vol:/var/lib/ghost \
  ghost

```

**Line-by-Line Explanation:**

1.  `docker run -d`: Runs the container in **detached mode** (background).
2.  `-e NODE_ENV=development`: Sets the environment to development mode.
3.  `-e url=http://localhost:3001`: Configures the base URL for the CMS.
4.  `-p 3001:2368`: **Port Forwarding**. Maps port 3001 on your host to port 2368 inside the container.
5.  `-v ghost-vol:/var/lib/ghost`: **Mounts** the volume `ghost-vol` to the internal path `/var/lib/ghost`, where Ghost stores its data.
6.  `ghost`: Specifies the official Ghost image to use.

### Common Mistakes

  * **Incorrect Path**: If you mount the volume to the wrong internal path (e.g., `/var/lib/data` instead of `/var/lib/ghost`), the application won't see the persisted data.
  * **Port Conflicts**: Ensure port 3001 isn't already in use by another service on your host machine.

### Key Takeaways

  * The `-v` flag is critical for persistence; it connects a host-managed volume to a container directory.
  * Environment variables (`-e`) are the standard way to pass configuration to containerized apps.

### Summary Notes

Using `-v` ensures that even if you delete the Ghost container, your blog posts remain safe in `ghost-vol`.

## Lecture 3: Volume Lifecycle Management

Managing volumes involves knowing how to inspect, remove, and automatically recreate them during development.

### Core Concepts

  * **Automatic Creation**: If you run a container with `-v` and the specified volume doesn't exist, Docker will create it for you automatically.
  * **Cleanup**: Volumes are not automatically deleted when a container is removed; they must be managed separately to save space.

### Syntax & Examples

**Managing Volumes via CLI:**

``` bash
# See all containers (including stopped ones)
docker ps -a

# List all existing volumes
docker volume ls

# Remove a specific volume
docker volume rm ghost-vol

```

### Deep Explanation

When you delete a container and its associated volume, and then run the `docker run` command again with the same volume name, you start with a **fresh installation**. Docker sees the volume is missing, creates a brand new empty one, and the application treats it as a first-time setup. This is why the Ghost post was gone after deleting both the container and the volume—the "hard drive" was formatted.

### Key Takeaways

  * `docker volume ls` is your primary tool for verifying which volumes are taking up space.
  * The `-v` flag's ability to auto-create volumes is convenient but can lead to "zombie" volumes if you aren't careful with naming.

### Summary Notes

Volume management is a two-step process: managing the container that uses the data and managing the volume that holds the data.

## Final Docker Volume Cheat Sheet

| Command                           | Purpose                                                         |
| :-------------------------------- | :-------------------------------------------------------------- |
| `docker volume ls`                | Lists all volumes on the host.                                  |
| `docker volume rm [NAME]`         | Deletes a specific volume.                                      |
| `docker run -v [VOL_NAME]:[DEST]` | Mounts (and potentially creates) a volume.                      |
| `docker inspect [VOL_NAME]`       | Displays detailed info about a volume (e.g., mount point).      |
| `docker ps -a`                    | Shows all containers to help identify which might use a volume. |

**Critical Paths to Remember:**

  * **Ghost Data Path**: `/var/lib/ghost` (Standard location for persistence in Ghost).
  * **Port Mapping**: `[Host Port]:[Container Port]`.
